Current Features

Architecture
- Language: Go
- CLI framework: Cobra
- Config loading/saving: Viper
- Interactive task UI: Bubble Tea + Bubbles + Lip Gloss
- Git operations: go-git plus native git commands where needed
- Provider API calls: net/http

Commands
- `setup`: enables hook and runs provider setup in one step
- `enable`: installs hook and selects provider type
- `disable`: removes managed hook and optionally removes config
- `hook_precommit`: primary pre-commit runtime command
- Compatibility aliases: `hook`, `hook run`

Hook Script Behavior
- Managed `.git/hooks/pre-commit` runs `go run . hook_precommit` when local Go runtime is available.
- Falls back to `git-enterprise-hooks hook_precommit` when installed binary is available.

Configuration Model
- Config file: `git-enterprise-hooks.yaml` in repository root (unless overridden with `--config`).
- Provider blocks:
    - `provider_jira` (`url`, `user_email`, `jira_api_token`, `project`)
    - `provider_github` (`url`, `github_pat`, `project`)
    - `provider_azure_devops` (`url`, `personal_access_token`, `project`)
- Only the active provider block is persisted when config is saved.

Runtime Environment Loading
- Automatically loads `.env` and `.env.local` from current working directory and repository root.

Env Fallbacks
- Token fallbacks:
    - GitHub: `GITHUB_PAT`, `GITHUB_TOKEN`
    - Jira: `JIRA_API_TOKEN`, `JIRA_TOKEN`
    - Azure DevOps: `AZURE_DEVOPS_PAT`, `AZURE_DEVOPS_EXT_PAT`, `SYSTEM_ACCESSTOKEN`
- URL/project fallback env vars:
    - GitHub: `GITHUB_URL`, `GITHUB_PROJECT`
    - Jira: `JIRA_URL`, `JIRA_USER_EMAIL`, `JIRA_PROJECT`
    - Azure DevOps: `AZURE_DEVOPS_URL`, `AZDO_URL`, `AZURE_DEVOPS_PROJECT`, `AZDO_PROJECT`

Pre-Commit Runtime Flow
1. Optionally skip validations only for VS Code SCM non-interactive commits.
2. Ensure active provider config is complete (prompt and save if interactive).
3. Search provider tasks by key/title.
4. Task selection behavior:
     - no task: use placeholder values and skip branch validation
     - one task: auto-select and print selection message
     - multiple tasks in TTY: interactive chooser
     - multiple tasks in non-TTY: auto-select first task
5. Enforce branch pattern if `rules.verify_branch_name` is configured.
6. Ask commit summary and optional task-title override.
7. Render commit message template and write to:
     - `.git/git-enterprise-hooks-message.txt`
     - `.git/COMMIT_EDITMSG`

Validation and UX Details
- GitHub issue keys are displayed as `#<number>`.
- Branch validation normalizes task key for matching (`#1` -> `1`).
- Hook command errors avoid noisy usage output.
- Top-level CLI errors are printed in red with `Error:` prefix.

Provider Support
- Jira
- GitHub
- Azure DevOps

Error Message Management
- User-facing error messages are centralized in `internal/errs/messages.go`.
